# Data Model

## Static plan data (generated, committed)

Generated by `scripts/convert_xlsx.py` from `~/Desktop/Sub_3-45_NYC_Marathon_Plan.xlsx`.

### `src/data/plan.json`

```jsonc
{
  "meta": {
    "goal": "3:45 marathon (~8:35/mile)",
    "race": "NYC Marathon",
    "raceDate": "2026-11-01",
    "startDate": "2026-05-25"
  },
  "weeks": [
    {
      "id": "BB-1",            // "BB-1".."BB-3" or "1".."20"
      "phase": "Base Building", // Base Building | Base | Hills | Intervals | Tempo/MP | Peak | Taper | Race
      "weekOf": "2026-05-25",   // Monday of the week
      "targetMiles": 23,        // planned run miles (number; travel weeks keep raw text too)
      "targetMilesText": "23",  // raw cell, for weeks like "18 default / A: 22-25 ..."
      "liftDays": "4",
      "isCutback": false,
      "travel": null            // null | "italy" | "wedding"
    }
  ],
  "days": {
    "2026-06-10": {
      "weekId": "BB-3",
      "dow": "Wednesday",
      "raw": "5 mi\nEasy (HR 135-145)",   // exact original cell text, always preserved
      "run": {
        "miles": 5,
        "type": "easy",   // easy|long|hills|threshold|vo2|tempo|mp|shakeout|strides|race
        "hrZone": "HR 135-145",
        "pace": null,      // e.g. "8:35/mi" when specified
        "structure": null, // e.g. "2 mi wu + 8 x 30s uphill (RPE 8-9) + cd"
        "fueling": null    // e.g. "3 gels + 2 SaltStick + 20oz/hr water"
      },
      "lift": null,        // { "focus": "Chest/Tri", "notes": "stack or PM" }
      "rest": false,
      "notes": null
    }
  }
}
```

Parsing approach: each spreadsheet cell is free-text multi-line. The converter uses
heuristics (leading `N mi` regex → miles; keywords → type; `HR x-y` → hrZone; `LIFT:` lines
→ lift; gel/SaltStick/water lines → fueling; remaining lines → structure/notes) and always
keeps the verbatim cell in `raw` so nothing is ever lost. Weekly mileage is validated
against the sheet's "Run Miles" column at convert time (hard fail on mismatch).

### `src/data/reference.json`

Structured content of the three reference sheets, as ordered sections of
`{ heading, items: [{ term, body }] }`:

- `travel` — core principles, Italy trip (incl. Wk-4 scenarios A/B/C), wedding trip
  (incl. Wk-10 scenarios A/B/C), general tips, red flags
- `fueling` — during-run targets, gel options, sodium, combos, hydration, gut training,
  race week/day, open items
- `paces` — goal/pace zones, weekly mileage rationale, structure logic, lifting, HR notes

## Dynamic data (Supabase)

See `supabase/schema.sql`.

```sql
day_log (
  date date primary key,
  run_done boolean default false,
  lift_done boolean default false,
  addon_done boolean default false,  -- stretch/recover add-on check-off
  actual_miles numeric,
  actual_pace text,
  notes text,
  updated_at timestamptz default now()
)

day_override (
  date date primary key,
  patch jsonb not null,   -- partial Day: {run?, lift?, addon?, rest?, skipped?, swappedWith?}
  updated_at timestamptz default now()
)

settings (
  key text primary key,    -- e.g. 'travel.italy', 'travel.wedding'
  value jsonb not null,    -- e.g. {"scenario": "B"}
  updated_at timestamptz default now()
)
```

### Settings keys

| Key | Value | Visibility |
| --- | --- | --- |
| `travel.italy`, `travel.wedding` | `{scenario}` travel-week pick | public |
| `strava.status` | non-secret mirror: connected/subscribed flags, last sync | public |
| `strava.tokens` | Strava OAuth `{access_token, refresh_token, expires_at, athlete_id}` | **secret** |
| `push.subscriptions` | array of owner devices' Web Push subscriptions | **secret** |

Keys flagged **secret** match `isSecretSetting()` (`src/lib/db.ts`) and are stripped from
the public `GET /api/state` — the site is publicly readable, so tokens and push endpoints
must never leave the server.

### Override semantics

- Edit: `patch` carries replacement `run`/`lift`/`addon` fields; merge is shallow per
  top-level key.
- Add-on (`addon`): an optional `{label, notes}` stretch/recover/mobility session. It only
  ever exists via an override (the static plan never carries one) and renders as its own
  card with a separate `addon_done` check-off. Add/remove it in the day editor.
- Skip: `patch = {"skipped": true}` — day renders struck-through, excluded from planned-miles.
- Swap (within a week): both dates get patches carrying the other day's planned content,
  plus `swappedWith: "<date>"` for the badge/revert.
- Revert: delete the row.

## Lift schedule remap (converter transform)

The workbook still encodes the original 4-day lift split (Mon Legs / Tue Chest-Tri /
Thu Back-Bi / Fri Shoulders-Arms). `remap_lifts()` in `scripts/convert_xlsx.py` rewrites
this at conversion time into the current 3-day split — **Mon Chest/Tri · Wed Back/Bi ·
Sun Legs** — by relocating each week's existing lifts *by focus* onto fixed days, and
**dropping Shoulders/Arms** (folded into push/pull). Reduced/travel weeks keep their
reduced lift count (nothing is invented; an unplaceable focus is simply left off). Stretch
that used to live on the Friday Shoulders/Arms cell is now the per-day `addon` instead.
To change the schedule, edit `LIFT_TARGET_DOW` / `LIFT_DROP` and re-run the converter —
never hand-edit `plan.json`.
